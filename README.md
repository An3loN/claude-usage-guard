# usage-guard

Плагин для Claude Code, который бережёт лимиты плана Claude (Pro / Max):

- каждый запрос грубо оценивается как лёгкий, средний или сложный;
- при 90%+ любого окна лимита (5-часового или недельного) сложный запрос ждёт сброса лимита и потом выполняется, лёгкие и средние выполняются сразу;
- большая задача, дошедшая до 90%, встаёт на паузу перед следующим вызовом инструмента и продолжается после сброса;
- при 98% ждут все задачи; если до сброса больше 5,5 ч (недельный лимит), задача останавливается с сообщением.

Средняя задача считается сложной после 8 вызовов инструментов, лёгкая — после 25, любая — сразу при запуске субагента.

## Требования

- Claude Code с входом по подписке Claude (Pro или Max).
- Node.js в `PATH` (`node -v`).

## Установка

В Claude Code:

```
/plugin marketplace add An3loN/claude-usage-guard
/plugin install usage-guard@usage-guard-tools
```

Или из терминала:

```bash
claude plugin marketplace add An3loN/claude-usage-guard
claude plugin install usage-guard@usage-guard-tools
```

Вместо `An3loN/claude-usage-guard` можно указать git-URL или путь к локальной копии репозитория. После установки перезапустите Claude Code.

### Откуда плагин берёт проценты лимита

- **Десктоп-приложение Claude (вкладка Code):** настраивать ничего не нужно. Когда данные устаревают, хук просит Claude вызвать встроенный инструмент `get_usage` и сохраняет результат (около 1 тыс. токенов за обновление; раз в 20 мин при низком расходе, раз в 2 мин ближе к лимиту).
- **Терминальный `claude`:** проценты приходят только через строку состояния, а плагин не может настроить её сам. После первого запроса в любой сессии выполните `/usage-guard statusline-setup`, и Claude добавит её в `~/.claude/settings.json`. Без неё в терминале guard никогда не ставит паузу.

Пока данных о лимитах нет, guard ничего не откладывает.

## Управление

| Команда | Что делает |
|---|---|
| `/usage-guard status` | состояние, пороги, проценты по окнам, очередь |
| `/usage-guard on` / `off` | включить / выключить guard |
| `/usage-guard release` | снять текущую паузу (из другой сессии или терминала) |
| `/usage-guard set <ключ> <значение>` | `threshold_pct` (90), `hard_pct` (98), `warn_pct` (80), `prompt_mode` (`wait` / `block`), `max_wait_hours` (5.5), `reset_buffer_sec` (60) |
| `/usage-guard queue` / `clear-queue` | отложенные запросы в режиме `block` |
| `/usage-guard classify <текст>` | как будет оценён запрос |

Метки в запросе: `!force` — выполнить без проверки, `!heavy` / `!light` — задать сложность вручную.

Приостановленная сессия сама ничего выполнить не может. Снять паузу можно из другой сессии командой `/usage-guard release` или из терминала:

```bash
node "$(cat ~/.claude/usage-guard/script-path)" release
```

## Что нужно знать

- Хуки работают во всех сессиях пользователя. На каждом вызове инструмента запускается `node`, это примерно 50–100 мс.
- Пауза идёт внутри хука с таймаутом 6 ч. Если клиент прервёт долгий хук, задача продолжится без паузы.
- Данные и журнал лежат в `~/.claude/usage-guard/`.
- Если usage-guard уже был подключён вручную через `~/.claude/settings.json`, уберите те записи перед установкой плагина, иначе хуки будут срабатывать дважды.

## Удаление

```
/plugin uninstall usage-guard@usage-guard-tools
```

Если добавляли строку состояния, уберите `statusLine` из `~/.claude/settings.json`.
